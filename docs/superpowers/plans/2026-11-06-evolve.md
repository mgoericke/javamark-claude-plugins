# evolve Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `evolve` Claude Code plugin: a command and skill that develop an existing app in rounds and blocks (modes invent and modernize), with scripts for scan, guardrails, ship and usage, plus a local dashboard.

**Architecture:** The judgement lives in Markdown (command, skill, references) and is carried out by Claude. Everything that must be measured or repeated exactly lives in small Node ESM scripts under `scripts/`, which read and write `.evolve/` in the target repo. The dashboard is a dependency-free Node HTTP server plus static UI that reads the same `.evolve/` data and starts old rounds from git worktrees.

**Tech Stack:** Node ≥ 20 (ESM, `node:test`, `node:http`, `child_process`), Playwright, pixelmatch, pngjs, optional Lighthouse; Basecoat 1.1.0 CSS + Geist font (vendored); git.

**Spec:** `docs/superpowers/specs/2026-11-05-evolve-design.md`. Visual target: `plugins/evolve/docs/dashboard-mock.html`, flow: `plugins/evolve/docs/flow.html`.

## Global Constraints

- Plugin lives in `plugins/evolve/` with `.claude-plugin/plugin.json`; registered in `.claude-plugin/marketplace.json` and the root `README.md`. Repo language English; dashboard UI text German (the mock's wording).
- Runs on macOS and Linux with Node ≥ 20 and git. No build step anywhere.
- Node dependencies are installed into `~/.cache/evolve/<plugin version>/`, never into the plugin folder or the target repo.
- Never push, merge or delete branches. Work happens on branch `evolve/<run-name>`; tag per round `evolve-<run>-r<NNN>` (NNN zero-padded to 3).
- All run data under `<target>/.evolve/`: `evolve.json`, `COMPASS.md`, `ROADMAP.md` (modernize), `CHANGELOG.md`, `TRIAGE.md` (review), `rounds/rNNN/`, `usage.json`, `dashboard.log`, `worktrees/` (git-ignored).
- Hard-guardrail defaults: Lighthouse performance and accessibility at most −5 points vs round 0, CLS at most +0.05 vs round 0. Max fix attempts per round: 3. Smoke viewports: desktop 1280×800 and mobile 390×844.
- Dashboard binds to `127.0.0.1` only; at most 2 round apps running at once, oldest stopped first.
- Cost is always labelled an estimate ("Schätzung"); prices come from an editable table in `evolve.json`.
- Unit tests run with `node --test plugins/evolve/scripts/test plugins/evolve/dashboard/test` and need no network or installed dependencies; tests that need Playwright skip themselves when it is missing.

## Review Focus

- **Start command never answers or the port is taken** → `startApp` gives up after its timeout with a clear message and kills the whole process group (no orphaned servers). Test in Task 2.
- **A route redirects to a login page, returns 404 or 500** → the smoke check records that route as failed with its status; the scan does not crash. Test in Task 3.
- **Transcript file is being written while read (half last line, non-JSON lines)** → usage skips bad lines and still sums the rest. Test in Task 6.
- **Target repo has uncommitted changes or the round tag already exists** → `start` refuses on a dirty tree; `ship` refuses to overwrite an existing tag and never commits files outside the round's work (`.evolve/worktrees/` stays ignored). Tests in Tasks 1 and 5.
- **Dashboard file URL with `../`** → 404, never a file outside `.evolve/rounds/`. Test in Task 7.

### Task 4: Guardrails

**Interfaces:**

  - `GuardrailResult = { pass: boolean, hard: Check[], soft: Check[] }`, `Check = { name: string, pass: boolean, value: string|number, baseline?: string|number, delta?: number, detail?: string }`. CLI flag `check.mjs <repo> --record-characterisation`.
